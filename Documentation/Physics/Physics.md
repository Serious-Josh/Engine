# Physics
Engine uses Box3D for it's 3D physics engine and currently supports three types of colliders:
- Box
- Sphere
- Capsule

Each collider can be used with Static, Dynamic, or Kinematic rigid bodies.

## Collision Events and Notifications

Engine processes physical contact information from Box3D into two phases:
### 1. Contact Events

Contact Events are records generated by Engine using Box3D's collision data. They are generated when two physics objects begin or end colliding.\
Each Contact Event contains:

    Event Type
        - Begin - Two objects begin touching
        - End - Two objects end touching
    Object A - Stable scene-object ID of the first object
    Object B - Stable scene-object ID of the second object
    Step Number - The fixed physics step when the event occured
Object A and Object B are ordered by their stable IDs.

Contact Events are always generated regardless of if either object has **Generate Contact Events** enabled or disabled.

### 2. Contact Notifications

Contact Notifications are records created when Engine determines that at least one object in a Contact Event has **Generate Contact Events** enabled.\
Each Contact Notification contains:

    CollisionEvent - The original contact event, including it's type, object IDs, and step number
    notifyObjectA - Whether Object A has opted into contact notifications
    notifyObjectB - Whether Object B has opted into contact notifications

If neither object has **Generate Contact Events** enabled, no Contact Notification will be generated.\
If both objects have it enabled, Engine generates a notification with both flags set to `true`.\
Contact Notifications do not affect normal physical collision response. Objects remain solid and will interact normally.

**Note**: Contact Notifications are currently only stored, and not delivered to gameplay scripts yet. This will be changed when AngelScript integration is introduced, and will allow objects to respond via collision callbacks.
